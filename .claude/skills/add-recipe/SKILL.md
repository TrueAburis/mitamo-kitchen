# レシピを1件追加する

## このスキルが守っていること

このサイトの存在理由は「作りながら見られるレシピ」で、その中身は
**手順を読んでいる間、その手順で使う分量が画面から消えないこと**。
だから、レシピを足す作業のうち一番大事なのは見た目ではなく
`data-uses` の中身が正しいかどうかになる。ここが雑だと、サイトの主張そのものが崩れる。

もう1つは日英の対。海外から日本の家庭料理を作りたい人が第2のターゲットで、
その人たちは店頭で材料のパッケージと照らし合わせる。だから材料名は言語を切り替えても
両方が出たままになっている。英語を後回しにすると、この人たちには使えないページになる。

方針の全体は `CLAUDE.md` にある。矛盾を感じたらそちらが優先。

## 手順

### 1. 材料がそろっているか確認する

必要なもの。足りないものは**推測で埋めずに聞く**。
それらしい嘘のレシピは、実際に作った人に迷惑がかかる。

- 料理名（日本語・英語）
- リード文と紹介文（日本語。英語は訳してよい）
- 何人前、かかる時間
- 材料と分量（グループが分かれるならその名前も）
- 手順の文章
- コツ（あれば）
- 写真（無ければ枠だけ作り、TODO を残す）

英語版は、既存の `tori-negi-meshi.html` と同じ粒度で書く。
機械的な直訳ではなく、日本語で書かれている情報が全部English側にもある状態にする。

### 2. slug を決める

ローマ字、小文字、区切りはハイフン。ファイル名と `<article id>` と画像名に使う。
例：鶏ネギ飯 → `tori-negi-meshi`

### 3. レシピページを作る

`tori-negi-meshi.html` を複製して中身を差し替えるのが速く、崩れにくい。

```bash
cp tori-negi-meshi.html <slug>.html
```

差し替える場所は次のとおり。

| 場所 | 内容 |
|---|---|
| `<title>` | `料理名｜みたもっちゃんねる` |
| `<meta name="description">` | その料理を1〜2文で。トップの説明文を使い回さない |
| `<article id>` | slug |
| `h1.recipe-title` | 料理名。`<span class="en">` に英語名 |
| `.recipe-intro` | 紹介文。`t-ja` / `t-en` の対 |
| `.recipe-meta` | 分量と時間 |
| `.qty-toggle` の「材料 N品」 | 実際の品数に直す。忘れやすい |
| `.qty-peek` | 主な材料3つ程度。手順を読み始めると自動で上書きされる初期表示 |
| `.qty-body` の `<dl>` | 材料。グループが2つ以上なら `h3.qty-sub` で区切る |
| `.qty-note` | 補足。無ければ段落ごと消す |
| `ol.steps` | 手順 |
| `.tips` | コツ。無ければ `div.tips` ごと消す |
| 写真の TODO コメント | slug に合わせる |

ヘッダーとフッターは全ページにコピーされているので、複製元のものをそのまま使えばよい。
ただし**ナビの `aria-current="page"` は「レシピ」に付いたままにする**（新しいページもレシピなので正しい）。

### 4. トップの「最新のレシピ」を差し替える

`index.html` の `#recipes` の中のパネルを、新しいレシピに置き換える。

- `.dish-name` を新しい料理名に
- `.dish-meta` を新しい分量・時間に
- `.qty-list` は**主な材料だけ**。タレや薬味などの副グループはトップに載せない
- `.shot` の TODO を新しい画像名に
- `.dish-more` の `href` を新しいページに

トップとレシピページを丸ごと同じ内容にしないこと。
同じものが2回続くと、2回とも読み流される。トップは入口で、続きがページにある状態を保つ。

### 5. ナビの行き先を直す

ヘッダーとフッターの「レシピ」は、いまは最新のレシピページを直接指している。
全HTMLの `href="<古いslug>.html"` のうち**ナビとフッターのものだけ**を新しい slug に変える。
トップの `.dish-more` は手順4で変えている。

レシピが3件を超えたら、一覧ページ `recipes.html` を作って
ナビの行き先をそちらに変える（`CLAUDE.md` に書いてあるとおり）。
そのときはこの手順も書き換える。

### 6. 確認する

`powershell -ExecutionPolicy Bypass -File serve.ps1` で `http://localhost:8000/` を開き、
ブラウザで自分の目で見る。最低でもこの4つ。

1. 幅375pxで横スクロールが出ないか（`scrollWidth == clientWidth`）
2. 手順をスクロールしたとき、分量バーの表示が手順に合わせて変わるか
3. 英語に切り替えて、日本語のまま残っている箇所がないか
4. **既存のレシピページが壊れていないか**（共通CSSを触ったときは特に）

### 7. 報告する

触ったファイル名と行数を書く。埋められなかった項目は TODO として明示する。
最後にコミットを促す。

```bash
git add . && git commit -m "レシピ追加：<料理名>"
```

## 分量の書き方

日本語と英語で単位が変わる。英語側は `tbsp` / `tsp` / `ml` / `g` に統一する。
海外の人が計量スプーンを持っている前提で書く。

```html
<dt>濃口醤油<span class="en">Soy sauce</span></dt>
<dd><span class="t-ja">大さじ2</span><span class="t-en">2 tbsp</span></dd>
```

材料名は `t-ja` / `t-en` を**使わない**。使うと切り替えで片方が消える。
`<span class="en">` は常に両方出るためのもの。ここを間違えやすい。

数値が言語で変わらないものは、対を作らずそのまま書く。

```html
<dt>水<span class="en">Water</span></dt>
<dd>400ml</dd>
```

## 手順と data-uses の書き方

各 `<li>` に、**その手順で使う材料と分量**を持たせる。これが分量バーに出る。

```html
<li data-uses="水 400ml ／ 醤油 大さじ2" data-uses-en="Water 400ml / Soy 2 tbsp"><span class="step-n">2</span>
  <p><span class="t-ja">…</span><span class="t-en">…</span></p>
</li>
```

書き方の約束。

- 区切りは日本語が全角スラッシュ `／`、英語が半角 `/`
- **手順の文章に出てこない材料を書かない。** バーと本文が食い違うと、作っている人が手を止める
- 材料を使わない手順（火にかけるだけ、盛り付けるだけ）は、代わりに火加減や状態を書く
  例：`data-uses="中火 → 沸いたら弱火 23分"` / `data-uses="盛り付け"`
- 1行に収まる長さにする。長いと省略されて読めない

## 待ち時間の書き方

手順の文章に時間が書いてあるときだけ、その手順の中に待ち時間を足す。
左の縦線の長さが、そのまま待ち時間の目盛りになる。

```html
<p class="wait wait-long"><span class="t-ja">弱火のまま 23分</span><span class="t-en">23 min on low</span></p>
```

- `wait-long`：10分以上
- `wait-short`：10分未満
- 書かれていない時間を足さない。推測した加熱時間は事故になる

## 写真

`images/<slug>.jpg` に置く。Instagram の投稿をそのまま使う前提なので、
1:1 でも 4:5 でも 9:16 でも枠が崩れないようにしてある。

まだ無いときは、既存の `figure.shot` の中身（「写真がまだありません」とファイル名）を
slug に合わせて書き換えて残す。空の `<img>` を置いて画像切れにしない。

写真を入れるときは `alt` を必ず書く。「料理名の写真」ではなく、
何が写っているかを書く（例：`炊き上がった鶏ネギ飯に刻みネギのタレをかけたところ`）。

## やってはいけないこと

- 情報が無い項目を、それらしい文章で埋める
- 英語版を機械的な直訳で済ませる、または後回しにして日本語だけ先に出す
- 新しい色を直接書く（色は `:root` の CSS変数だけ）
- 手順を角丸カードに切り分ける、意味のない番号ラベルを足す
- レシピ1件のために CSS を大きく増やす。既存のクラスで足りないか先に確かめる
