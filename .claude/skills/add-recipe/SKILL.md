# レシピを1件追加する

## このスキルが守っていること

このサイトの存在理由は「作りながら見られるレシピ」で、その中身は
**手順を読んでいる間、その手順で使う分量が画面から消えないこと**。
だから一番大事なのは見た目ではなく、手順1つ1つに付ける `usesJa` / `usesEn` の中身。
ここが雑だと、サイトの主張そのものが崩れる。

もう1つは日英の対。海外から日本の家庭料理を作りたい人が第2のターゲットで、
その人たちは店頭で材料のパッケージと照らし合わせる。だから材料名は
英語ページでも日本語を併記している。

方針の全体は `CLAUDE.md` にある。矛盾を感じたらそちらが優先。

## 大前提：HTMLは書かない

**`dist/` の中のHTMLを手で作らない・直さない。次の `npm run build` で消える。**
書くのはデータだけで、ページは組み立てが作る。

```
data/captions/<slug>.txt   キャプション本文（もらったものをそのまま置く）
        ↓  node tools/generate.ts
content/<slug>.js          レシピ本文（材料・手順・コツ）
data/recipes.ts            一覧に出す情報（タイトル・タグ・投稿URL）
        ↓  npm run build
dist/<slug>.html + dist/en/<slug>.html
```

## 手順

### 1. 材料がそろっているか確認する

必要なもの。足りないものは**推測で埋めずに聞く**。
それらしい嘘のレシピは、実際に作った人に迷惑がかかる。

- 料理名（日本語・英語）
- リード文と紹介文
- 何人前、かかる時間
- 材料と分量（グループが分かれるならその名前も）
- 手順の文章
- コツ（あれば）
- 写真（無ければ枠だけ作り、TODO を残す）

**PR（タイアップ）の回は自動掲載の対象外。** 載せると決まった回だけ手で足し、
PRである旨を画面に明記する。`tools/generate.ts` は `#PR` を見つけると終了コード 2 で止まる。

### 2. slug を決める

ローマ字、小文字、区切りはハイフン。ファイル名と画像名に使う。
例：鶏ネギ飯 → `tori-negi-meshi`

### 3. キャプションがあるなら、まず機械に起こさせる

キャプションを `data/captions/<slug>.txt` に置いてから実行する。

```bash
node tools/generate.ts data/captions/<slug>.txt <slug>
```

`content/<slug>.js` が書き出され、`data/recipes.ts` に貼る1件分が表示される。
**出た警告は必ず読む。** とくにこの2つは黙って通すと画面に出てしまう。

- 「材料の品数が日英で違うので、英語を順番で当てるのをやめた」
- 「対訳表の『…』がキャプションのどの行にも当たらなかった」（日本語が1字違うと当たらない）

キャプションが無く、材料と手順のテキストだけを渡された場合は、
`content/` の既存ファイルを見ながら手で書く。形は下の「本文データの書き方」。

### 4. content/&lt;slug&gt;.js を仕上げる

生成できるのは材料までで、**手順とその `usesJa` / `usesEn` は人が書く**。
キャプションに手順が無ければ `steps: []` のままにする。
**それらしい手順を書き足すことは絶対にしない。** 画面に「手順は準備中」と出る。

### 5. data/recipes.ts に1件足す

一覧・検索・タグ・人気順・ガチャは、すべて `data/recipes.ts` の `RECIPES` から作られる。
**本文を作っただけでは一覧に出てこない。**

```ts
{
  slug: '<slug>',
  ja: { title: '料理名', lead: '一行の説明' },
  en: { title: 'English name', lead: 'One line in English' },
  tags: ['chicken', 'vegetable'],
  image: 'images/<slug>.jpg',
  posted: '2026-09-07',
  instagram: 'https://www.instagram.com/reel/xxxx/',
  ready: true
}
```

- `tags` は `data/recipes.ts` の `TAGS` のキー。新しいタグを使うなら TAGS にも日英と軸を足す
- **いいね数などは書かない。** `data/instagram.json` から自動で合流する
- `posted` は**投稿日が分からなければ `null`**。今日の日付で埋めない。
  画面の日付も「新しい順」の並びも嘘になる
- `instagram` に投稿URLを入れると、動画が入り、いいね数の取り込み対象にもなる
- 手順がまだなら `ready: false`

ヘッダーのメニューと一覧ページは触らなくてよい。どちらもデータから作られる。

### 6. 組み立てて確認する

```bash
npm run check && npm test && npm run build
powershell -ExecutionPolicy Bypass -File serve.ps1
```

`http://localhost:8000/` をブラウザで開いて、自分の目で見る。最低でもこの5つ。

1. 幅375pxで横スクロールが出ないか（`scrollWidth == clientWidth`）
2. 手順をスクロールしたとき、分量バーの表示が手順に合わせて変わるか
3. 英語ページに、日本語のまま残っている箇所がないか
4. 一覧・ガチャ・関連レシピに新しい1件が出ているか
5. **既存のレシピページが壊れていないか**（共通CSSを触ったときは特に）

### 7. 報告する

触ったファイル名と行数を書く。埋められなかった項目は TODO として明示する。
最後にコミットを促す。

```bash
git add . && git commit -m "レシピ追加：<料理名>"
```

## 本文データの書き方（content/&lt;slug&gt;.js）

### 材料

```js
{ ja: '濃口醤油', en: 'Koikuchi soy sauce (standard Japanese soy sauce)',
  qja: '大さじ2', qen: '2 tbsp' },
```

- `en` が `null` は「訳を当てない」の意味。**間違った英語より日本語のまま**のほうが調べられる
- 英語の材料名は `tools/ingredients-ja-en.ts` の辞書を正とする。
  回ごとに違う英語を書かない（昆布が4回で4通りになった実例がある）
- 定訳を決めたら、`data/phrasebook.ts` の `TERMS` と辞書の両方に入れる。
  片方だけだと、その回だけキャプションの英語のまま出る

### 手順と分量の対応

各手順に、**その手順で使う材料と分量**を持たせる。これが分量バーに出る。

```js
{ ja: '鍋に水400mlと濃口醤油 大さじ2を入れます。',
  en: 'Put 400ml water and 2 tbsp soy sauce in the pot.',
  usesJa: '水 400ml ／ 醤油 大さじ2', usesEn: 'Water 400ml / Soy 2 tbsp' },
```

- 区切りは日本語が全角スラッシュ `／`、英語が半角 `/`
- **手順の文章に出てこない材料を書かない。** バーと本文が食い違うと、作っている人が手を止める
- 材料を使わない手順（火にかけるだけ、盛り付けるだけ）は、代わりに火加減や状態を書く。
  例：`usesJa: '中火 → 沸いたら弱火 23分'` / `usesJa: '盛り付け'`
- 1行に収まる長さにする。長いと省略されて読めない
- 待ち時間は手順の文章に書かれているときだけ書く。**推測した加熱時間は事故になる**

## 写真

`assets/images/<slug>.jpg` に置く。Instagram の投稿をそのまま使う前提なので、
1:1 でも 4:5 でも 9:16 でも枠が崩れないようにしてある。
組み立てのときに `dist/images/` へ写される。

まだ無いときは何もしなくてよい。画面に「写真がまだありません」とファイル名が出る。

写真を入れるときは `alt` を必ず書く。「料理名の写真」ではなく、
何が写っているかを書く（例：`炊き上がった鶏ネギ飯に刻みネギのタレをかけたところ`）。

## やってはいけないこと

- **`dist/` の中を直す**（次の組み立てで消える）
- 情報が無い項目を、それらしい文章で埋める
- 手順が無いレシピに、それらしい手順を書き足す
- 英語版を機械翻訳で済ませる。材料名は店頭で照合するためのものなので、
  薄口と濃口を訳し分けられない翻訳は目的に対して害になる
- 新しい色を直接書く（色は `:root` の CSS変数だけ）
- 手順を角丸カードに切り分ける、意味のない番号ラベルを足す
- レシピ1件のために CSS を大きく増やす。既存のクラスで足りないか先に確かめる
